# Stage 2 — Catalog: implementation plan

## Context

Stage 0–1 is merged (PR #1, #2) and CI is green. Stage 2 (`docs/build-stages.md`) is "Products/barcodes/UOM/price lists, import wizard, search"; exit criterion **5,000 SKUs imported; barcode lookup < 30 ms measured**. The LLD (§2.1, §10, §18) specifies tables, IPC surface and perf budgets, but there is no task breakdown, and gaps remain: `category`/`brand` are referenced but undefined, the import wizard is unspecified, scope (variants, weight barcodes, labels) and cloud involvement are open, and `name_norm` rules for Indic names are undefined.

Decisions taken (user approved defaults):
- **Scope:** products, multiple barcodes (incl. case barcodes), UOM + per-product conversions, categories, brands, price lists (qty breaks, effective dating), search, CSV/XLSX import, UI. `product_variant` table is created (schema-ready) but **no variant UI/API**. Weight-embedded barcodes (FR-101) and label printing (FR-107) are **deferred** (not in Stage 2).
- **Device-local catalog:** no Go/OpenAPI changes. Every mutation writes audit + outbox rows as in Stage 1 (ADR-0006); Stage 7 ships them.
- **Import:** two-phase — `importPreview` validates every row and returns per-row errors; `importCommit` is one all-or-nothing transaction.

First deliverable of the implementation: copy this plan to `docs/plans/stage-2-catalog.md` (new `docs/plans/` folder, linked from `docs/README.md`).

## Design decisions (each gets an ADR, next numbers 0008–0012)

| ADR | Decision |
|---|---|
| 0008 | Catalog is device-local until Stage 7; outbox entity types extended (`product`, `barcode`, `uom`, `uom_conversion`, `category`, `brand`, `price_list`, `price_list_item`); variants/FR-101/FR-107 deferred with schema kept ready. |
| 0009 | Search = `name_norm` prefix index (cashier typing) + FTS5 table `product_fts(name, sku, hsn_code, brand_name)` tokenizer `unicode61 remove_diacritics 2`, **maintained by the repository in the same transaction** (not triggers, because `brand_name` is denormalised and a brand rename must reindex). `normalizeName`: NFKC → lowercase → strip combining marks **only when the base char is Latin** (stripping Mn in Devanagari etc. would delete matras/virama) → collapse whitespace. |
| 0010 | Import transport: renderer sends file bytes (base64, cap 10 MB / 20,000 rows) — no paths over IPC (registry forbids `path`). Preview is held in main memory keyed by `importId` (TTL 15 min). Duplicate policy `skip \| update`, matched by SKU then barcode; a barcode owned by a different product is a row error. Commit is one transaction; any failure rolls back everything. CSV via `papaparse`, XLSX via `exceljs`. |
| 0011 | Selling price lives in the **default price list** (`Retail`, seeded per business), not a `product` column. `product.mrp_paise` / `purchase_price_paise` stay on product. Validation: inclusive price ≤ MRP when MRP set. Price resolution is a pure domain function (TS only for now; Go port when the cloud needs it — noted against ADR-0001). |
| 0012 | Hot-path statement cache: `stmt(db, sql)` (WeakMap<Db, Map<sql, Statement>>) in db-sqlite for lookup/search; plus a 500-entry LRU of barcode → ProductHit in the service, invalidated on any product/barcode/price mutation. |

Design doc changes in the same commit as the code they affect: LLD §2.1 (add `category`, `brand`, `product_fts`; drop "selling price on product"), LLD §10.2 (final `products.*`/`catalog.*`/`pricing.*` surface), `docs/architecture.md` (catalog module + invariants).

## IPC surface (one dot per channel; mutations `audit: true`)

- `products.search {query, limit≤50, mode: auto|barcode|name|sku}` → `ProductHit[]` (perm `products.view`, 30/s)
- `products.lookupBarcode {code}` → `ProductHit | null` (includes scanned UOM, pack qty, resolved default price)
- `products.list {cursor?, limit, categoryId?, brandId?, includeInactive?}`, `products.get {id}`
- `products.create`, `products.update {id, expectedVersion, ...}`, `products.deactivate`, `products.reactivate` (perm create/edit)
- `products.importPreview {fileName, contentBase64, mapping?}` → `{importId, columns, suggestedMapping, rows[{line, status: ok|error|duplicate, errors[]}], counts}`; `products.importCommit {importId, duplicatePolicy, commandId}` (idempotent on `commandId`) → summary
- `catalog.listUoms / createUom / listCategories / createCategory / updateCategory / listBrands / createBrand / updateBrand`
- `pricing.listLists / createList / getItems / setItems` (IPC namespaces must be lowercase)

`ProductInput` carries barcodes[], conversions[], and `sellingPricePaise` (written to the default list) so one form = one transaction.

## Delivery

One branch `feat/stage-2-catalog`, **one PR** for all of Stage 2. Parts 2a–2e below are **commits** on that branch (each green locally with its CHANGELOG line), not separate PRs. **Nothing is pushed and no PR is opened until the user has reviewed the local branch.**

## Tasks (each: test first, then code; each part is one commit)

**Part 2a — Domain + schema**
1. `packages/domain/src/catalog/`: `normalizeName`, `validateBarcode` (EAN-13/EAN-8/UPC-A checksum; `CODE128` free-form), `convertQty` (UOM factor_milli → base milli, integer, uses `divRound`), `resolvePrice(items, {uomId, qtyMilli, at})` (highest `min_qty` ≤ qty, effective window, falls back to base UOM × factor). Tests: fixture tables + fast-check (convert round-trip, resolve picks a single deterministic item, Devanagari names unchanged except case/whitespace).
2. `0002_catalog.sql`: `uom`, `uom_conversion`, `category` (parent_id, name, name_norm), `brand`, `product`, `product_variant` (no API), `barcode`, `price_list`, `price_list_item`, `product_fts` + indexes from LLD (`ux_barcode` partial, `ix_product_active`, unique SKU partial on `deleted_at IS NULL`), all with standard sync columns. Tests: migrate fresh + from v1, `foreign_key_check`, schema-lint passes, FTS5 available in bundled better-sqlite3.
3. Extend `OutboxEntityType`; add `stmt()` cache (ADR-0012).
4. ADRs 0008, 0009, 0011, 0012; LLD §2.1 update; `docs/plans/stage-2-catalog.md`; build-stages Stage 2 → **In progress**.

**Part 2b — Repositories + services + contracts**
5. Repositories `uom.ts`, `category.ts`, `brand.ts`, `product.ts` (writes product + barcodes + conversions + default price item + FTS row in one tx), `priceList.ts`, `catalogDefaults.ts` (`ensureCatalogDefaults(db, businessId, actor)`: idempotent seed of UOMs PCS/KG/G/L/ML/M/DOZ/BOX/CASE and the `Retail` default list). Tests per `repositories.test.ts` pattern: row+audit+outbox counts, rollback on duplicate barcode, version conflict, soft-deactivate hides from search, brand rename reindexes FTS.
6. Hook `ensureCatalogDefaults` into business creation and session start (covers Stage 1 businesses).
7. Contracts (schemas + registry entries) → regenerate preload; `CatalogService`, `ProductService`, `PriceListService` wired in `app.ts`. Tests: gateway-level via `testApp()` — cashier can search but not create, validation errors mapped, `preload-surface` passes.

**Part 2c — Search + performance**
8. `products.search` auto mode: all-digits ≥ 8 → barcode exact, else SKU exact → `name_norm` prefix (`LIMIT 20`) → FTS5 token match to fill; stable ordering. Barcode LRU (ADR-0012).
9. `apps/desktop/test/perf/catalog.perf.test.ts`: seed 5,000 products (+ ~7,500 barcodes); assert p95 of 1,000 random barcode lookups < 30 ms and p95 prefix search < 60 ms, measured cold (no LRU) and warm. Runs in normal CI (fast).

**Part 2d — Import**
10. `ImportService`: parse (papaparse/exceljs), header auto-mapping (name, sku, barcode(s) `;`-separated, hsn, category, brand, uom, mrp, selling price, purchase price, gst %, reorder level), per-row validation via the same zod `ProductInput` + domain validators, in-file duplicates, DB duplicates, auto-create missing categories/brands/UOM-by-code. ADR 0010.
11. Commit: single `withTransaction`; idempotent `commandId`. Tests: golden CSV + XLSX fixtures in `apps/desktop/test/fixtures/import/` (good file, errors file, duplicates file); failure mid-commit leaves zero rows; **5,000-row import commits in < 10 s** and every product is barcode-searchable afterwards (the exit-criterion test).

**Part 2e — UI**
12. Routes `/products` (search box, debounced 120 ms, list with filters, deactivate), `/products/new` & `/products/:id` (form: basics, tax, barcodes list, UOM conversions, prices per list), `/products/import` (upload → mapping/preview with row errors → summary), `/settings/catalog` (UOMs, categories, brands, price lists). Enable NAV. Tests: component tests for the import wizard states; manual run via the `run` skill.
13. Docs close-out: build-stages Stage 2 → **Done** with measured numbers, architecture.md catalog section, LLD §10.2 surface, CHANGELOG.

## As built (2026-09-30)

- Search orchestration and the barcode LRU landed in Part 2b with the services; Part 2c is the performance test.
- Price-list channels are `pricing.*`, because IPC namespaces must be lowercase.
- `product_search_key` was added so FTS rows are deleted by rowid; without it saves slowed down as the catalog grew.
- Import rows with errors are skipped and counted rather than blocking the commit; any exception still rolls back all.
- The renderer has no DOM test setup, so the screens' logic (money parsing and display, form ↔ `ProductInput`, price
  rows) lives in `src/renderer/src/lib/` with node tests; the screens themselves were not clicked through.
- A review pass (Part 2f) fixed pack-price MRP scaling, merged-row validation in the import preview, xlsx blank headers
  and float formulas, the stale selling price on the product form, price date checks, catalog settings validation,
  preview expiry, CSV line numbers, per-row list queries and barcode pack quantities on the form.
- A second review pass (Part 2g) moved the price-vs-MRP rule into the database layer for every live price, carried the
  stored price through updates that omit it, sent barcode details only for untouched rows, closed the remaining
  import-commit failures (same product twice, other-list pack prices, deleted owners; per-row savepoints), and fixed
  comma-only CSV rows and 16-digit xlsx codes.
